# Визуализация графа зависимостей NuGet (вариант 26)

## 1. Общее описание

Учебный проект по конфигурационному управлению (РТУ МИРЭА, ИКБО-23-25).
Инструмент командной строки: строит граф зависимостей .NET-пакета
и показывает его в удобном виде. Готовые менеджеры пакетов и сторонние
библиотеки для получения зависимостей не используются — только
стандартная библиотека Python. Работа выполнена поэтапно, каждому этапу
соответствует ветка `stage-N`.

## 2. Функции и настройки

Настройки задаются только опциями командной строки:

| Опция | Назначение |
| --- | --- |
| `--package` | имя анализируемого пакета (обязательно) |
| `--repo` | URL репозитория NuGet или путь к файлу тестового репозитория |
| `--test-mode` | режим тестового репозитория: `on`/`off` (по умолчанию `off`) |
| `--filter` | подстрока: пакеты с ней в имени исключаются из анализа |
| `--load-order` | показать порядок загрузки зависимостей: `on`/`off` |

Этап 1: программа выводит полученные настройки в формате ключ-значение.
Ошибки всех параметров обрабатываются и показываются пользователю:
отсутствие значения, пустое имя пакета, плохой адрес репозитория,
неверный флаг, слишком длинный фильтр.

Этап 2: программа обращается к репозиторию NuGet по протоколу V3
(регистрация, карточка версии, группы зависимостей) и выводит
прямые зависимости пакета — только первый уровень, без рекурсии.

Этап 3: в режиме `--test-mode on` граф читается из тестового файла
(строки вида `A: B C`, пакеты — большие латинские буквы) и строится
поиском в глубину без рекурсии (явный стек). Пакеты с подстрокой
фильтра пропускаются, циклы находятся и выводятся, программа
не зацикливается.

Этап 4: опция `--load-order on` выводит порядок загрузки пакета
(топологическая сортировка: сначала зависимости нижнего уровня).
Сравнение со штатным менеджером (`dotnet list package
--include-transitive`): порядок уровней совпадает, внутри одного
уровня менеджер сортирует по своим правилам, а инструмент — по
алфавиту; расхождение объясняется разными стратегиями упорядочивания
независимых пакетов, на корректность установки оно не влияет.

## 3. Сборка и запуск тестов

Сборка не требуется, нужен только Python 3. Тесты:

```sh
./run.sh
```

или вручную:

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -t . -v
```

## 4. Примеры использования

Вывод настроек:

```sh
PYTHONPATH=src python3 -m depgraph --package Newtonsoft.Json \
  --repo https://api.nuget.org/v3/index.json --filter test
```

Ожидаемый вывод:

```text
package=Newtonsoft.Json
repo=https://api.nuget.org/v3/index.json
test_mode=False
filter=test
```

Пример обработки ошибок:

```sh
PYTHONPATH=src python3 -m depgraph --package " " \
  --repo https://api.nuget.org/v3/index.json
```

```text
ошибка: имя пакета не должно быть пустым
```
